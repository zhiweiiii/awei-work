# Claude Code / Codex 配套功能

awei-work 使用用户已安装并登录的 CLI，模型权限和费用由对应服务决定。会话历史读本机记录，用量问 CLI 接口；两者不是同一数据。

## 会话历史与恢复

顶部菜单提供新对话 Claude Code/Codex，并把当前项目目录的历史合并，按最后活动时间排序。点记录通过正常提交入口执行 `claude --resume <UUID>` 或 `codex resume <UUID>`，不是只把文字插入输入栏。

Claude 从 `~/.claude/projects/<escaped cwd>/` 读取，Codex 从 `~/.codex/sessions/<年>/<月>/<日>/` 读取。Claude 目录转义可能碰撞，Codex 日期也不是项目归属；必须逐文件核对真实 cwd，不能只看路径。标题过滤环境及指令前言，无法找到真实标题就显示无标题，不猜。

每文件头部读取上限 192 KB；扫描结果缓存 2 秒/最多 32 目录，头部缓存最多 512 文件。扫描有项数、文件数、深度和时间预算，超限返回错误而非用部分结果判断唯一性。菜单只在打开时加载，回复绑定目录/环境/打开代次。历史读取 Windows 用户目录。

自动恢复最近 5 个非私密项目，持久化 `lastUsedAt` 和 `lastAgentSession`。身份由对应 PTY 的 agent 运行代次、固定记录文件、UUID/cwd 核对确认，不以最新文件代替当前会话。运行后约 1 秒检查，随后每 15 秒及退出保存时检查最近项目；没有 agent 时不周期读历史。

启动只恢复每个项目上次活动面板的一个 agent。验证确切记录后等待 PTY 和提示符就绪，预算 20 秒；隐藏面板临时绑定现有渲染器，不抢焦点。项目/面板关闭、目录改变、已有任务或用户已开始输入草稿均取消。记录缺失或超时不会新建对话、不会重放消息。旧版本未保存 UUID，升级后先运行一次会话并正常保存。

## 桌面宠物

宠物是任务提醒和项目跳转入口，不提供独立聊天面板。形象沿用用户提供的杯子 SVG，图标为 68×88，杯盖中央显示项目状态点，没有额外角标和杯身悬停提示。无任务时微笑，处理中为小哭脸，等待选择/确认时为焦急表情；杯身保持静止，不做持续浮动或焦点光晕。

### 进入对话

点击杯盖小点直接显示主窗口并切换到该项目、该分屏的现有 agent 会话；不会新建或恢复另一个会话。跳转在主线程执行，按 leaf、PTY 和 agent 运行代次核对，目标已关闭或重启时拒绝旧跳转。失败保留未读点并用一句气泡说明，不跳到其他项目。

杯身点击打开主窗口；有 agent 提醒时进入提醒对应会话，有定时提醒时点击杯身收起提醒。移动超过 6px 才开始原生拖动，松手不会误触打开。右键只保留“打开终端”“打开对话”项目列表和“隐藏宠物”，其中“打开对话”直接切换现有终端。更多项目可从杯盖“+数量”进入同一项目列表。

### 项目状态

每项目一个点，同项目分屏合并，不同项目即使同名或同目录也按项目 ID 区分。红色表示处理中，橙色表示选项待选、需要确认或步骤失败，绿色表示完成未读；状态读取失败时灰色并暂停点击。优先显示并定位待选面板，其次其他橙色、红色和绿色。待命且没有选项时无点，超过四个项目用前三点和“+数量”显示。

名单每两秒查询，agent 信号经 120ms 去抖提前刷新，焦点和可见项目变化立即刷新。待选状态在同一次查询中向主窗口批量读取实时终端菜单摘要，不传正文，不另建 xterm，不改变终端尺寸或焦点，不增加定时器。使用手机端已有菜单解析，只接受有选中标记的编号列表，普通编号正文不当菜单；CLI 格式变化可能无法识别，此时仍可直接去终端处理。

完成未读与短时气泡分开保存，关闭或超时不消绿点；成功进入并在主窗口查看对应面板后清除，跳转失败保留。同项目分屏分别确认，不因查看一个就清除其他结果。首次加载不把旧完成记录当新未读，退出 agent 或关闭项目后清理；未读与通知队列只在本次运行保留。

### 提醒气泡

主窗口在后台，或在前台但对应项目不在当前画面时可以提醒；当前正在查看的终端及同项目可见分屏不重复提示。通知用一句带项目名的短话展示开始、文字进展、出错、等待确认和完成结果，不显示思考过程；普通工具调用、读写文件和执行命令不单独弹气泡。

切换焦点、项目或重新显示宠物只刷新状态，不重复提示开始。同一确认轮次的阶段抖动和确认后继续处理不重报开始；新的步骤与结果仍可通知。普通进展合并限频，确认和结果优先，多项目排队有数量及时效预算。完成通知按轮次去重，结果文字更新不生成新通知，超过 30 秒不再弹出，包括排队和悬停时间。通知通常 8 秒收起，停留或聚焦暂停，完成通知仍受绝对时限约束。

点击状态气泡直接进入对应终端，点击外部、关闭按钮或 Esc 收起；菜单和拖动期间暂缓焦点判断，操作结束后核实原生焦点，丢弃旧检查结果。定时宠物提示沿用独立提醒队列。状态预览复用本轮、已核对的 transcript 快照，不再提供完整对话读取、消息发送、草稿或选项提交入口。

### 窗口与资源

窗口生命周期由 Rust 异步门闩串行处理。WebView 创建保持异步，创建后状态恢复、原生边界/区域和显隐排入主线程，避免后台持有 window-state 缓存锁再等待主线程。插件跳过恢复使用映射后的 pet-canvas-v1，缩放回调只合并排队刷新。

透明画布维持 796×1000，图标位置固定，通知出现和消失不改变窗口尺寸。Windows 原生区域只保留图标和最多 312×98 的气泡，其余画布不显示、不拦截点击；相同区域跳过更新，不强制重绘或开启系统阴影。通知随显示器空间选择上下方向，旧位置记录保留。宠物隐藏后停止名单轮询，旧异步回复不覆盖新范围。

主窗口真正销毁后标记正在退出，销毁辅助窗口并结束进程，拒绝迟到的恢复请求，不改写宠物开关；取消关闭保护不会销毁宠物。宠物不独立于主程序运行，也不需要更新器、进程控制或自启动权限。

## 用量

底栏先读缓存，再查询，面板关闭时也每 5 分钟更新。定时强制重读、手动刷新保留，在途查询合并；成功缓存 5 分钟，失败不缓存。前端保留上次值并标记失败，自动错误不连续弹通知。

- Claude：短生命周期 `claude -p "/usage"`，保留完整原文，只解析可识别的 Current session/week。不要用 transcript token 数冒充套餐百分比；引号不能省，以免 Git Bash 路径转换。
- Codex：短生命周期 `codex app-server --stdio`，initialize 后请求 `account/rateLimits/read`，不干预正在运行的 TUI，不读取或转发登录凭据；完成或超时即回收进程树。

常驻显示 `C:5h-33%(11:39) 周-50%(10/11) O:5h-...`，百分比 <75 绿、75–89 橙、≥90 红。5h 时间显示本地时分，周时间显示月日；无法确认数据/时间则 `--`，错误用 `!` 标记并在详情保留原文。Codex 按实际窗口时长匹配，不误标其他窗口。查询不发送普通编码消息，但本项目不替 CLI 或服务商承诺计费策略。

## 定时任务

支持多个单次/每日任务，按本机时区算下一次，不按固定 24 小时累加。应用必须运行，不唤醒睡眠或关机设备。

底栏定时消息按钮不显示任务蓝点提醒，点击后查看任务列表与执行状态。

- 终端：绑定 leaf，复用标准提交与去重。重启或原终端关闭后暂停，需手动绑定；已过期重新绑定会提示立即发送。
- Codex 后台：无窗口 `codex exec --skip-git-repo-check --color never -`。
- Claude 后台：无窗口 `claude -p --output-format text`。
- 宠物提示：到点自动打开宠物但不抢焦点，气泡直接显示填写内容，不启动 agent、不写终端。支持同样的单次、延时和每日循环。

后台模式不使用用户终端或用户指定目录，内部目录为 app-local-data 下 `scheduled-agent`；经 stdin 传消息，每次新会话，沿用本机登录与配置，不绕过权限检查。最多并行 4 个，30 分钟超时，stdout/stderr 各保留最多 16 KiB，Job Object 回收后代。取消不能撤回已到服务商的请求。

宠物提醒不受后台 CLI 并发名额限制，最多排队 128 条，逐条展示；窗口就绪后先监听再补取，避免冷启动漏消息。点击气泡、杯身或关闭按钮确认，通常 15 秒后自动收起，悬停/聚焦时暂停；长内容可滚动。任务本身持久化，已交付的气泡队列只在本次运行保留，重启不重放已交付提醒，也不标记项目未读。

任务保存在 app-local-data 的 `schedules.json`，开发版 `schedules-dev.json`；消息是明文，不放密钥。新增、取消及状态更新串行原子保存，损坏数据不被空队列覆盖；存储失败回滚或暂停调度，同类型实例用 Windows 锁防止重复运行。

执行前先保存 running，并在执行与完成时核对触发身份。重启发现未确认完成的单次任务标记中断，不自动重发；每日任务记录中断并安排下一次。不承诺模型请求与本地磁盘之间的恰好一次事务。

## Claude 供应商网关

`gateway/` 把 Anthropic Messages 转为兼容 OpenAI Chat Completions 或转发 Anthropic。仅监听 `127.0.0.1`，开发 34267、正式 34266，有本地令牌认证；配置只保存，真正使用该网关的 shell 启动时才监听。停止等待 socket 释放后才允许重启。

供应商按 leaf 的 `/p/<providerId>` 固定，不用全局选择改道其他终端；删除供应商返回失败，不默默换到别家。pin 不持久化、不自动继承。切换先检查前台任务，保留 cwd 重启，失败恢复 pin；探针是真实小请求，可能有费用。

环境在 spawn 时注入 `ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN`，清除冲突的 `ANTHROPIC_MODEL`/`ANTHROPIC_API_KEY`，不敲入终端历史。模型按 opus/sonnet/haiku 路由，剥除 `[1m]`。

转换核心 `convert.rs`、`stream.rs`、`sse.rs` 不碰 IO。SSE 处理跨 chunk UTF-8，最终只发一次 message_delta；include_usage、工具参数稳定序列化保留，上游错误/中断不补成功结束。reqwest 在 runtime 内构建/send，并主动安装 ring provider，不能依赖更新插件先初始化。

上游禁止重定向，有 64 MiB 响应、4 MiB SSE 事件及工具数量/参数预算。服务商特有头只按对应 host 加入；OpenCode Zen 的会话头使用稳定会话 ID。不增加自动故障转移、熔断或用量数据库。
