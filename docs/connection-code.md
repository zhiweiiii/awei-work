# 动态执行代码

连接页提供 SSH 终端和动态执行代码。动态代码使用独立 UTF-8 `.mjs` 文件，需要 Node.js 22+，按当前 Windows 用户权限执行。应用核心已移除浏览器连接，不再提供 Chrome RPC、扩展、网页步骤或 OCR。

默认目录是 `%LOCALAPPDATA%\app.crynta.terax\connection-scripts\`，每个连接一个文件，也可填写项目中的 `.mjs` 完整路径。agent 可直接修改文件；每次执行创建新的 Node 进程加载当前代码，不监控文件并自动运行。界面保存比较内容哈希，文件被外部修改后需重新读取。

| 接口 | 用途 |
| --- | --- |
| `launch(exePath, args = [])` | 用完整 `.exe` 路径和独立参数数组启动本机程序，不拼 shell |
| `username` / `password` | 当前连接的用户名和本次取得的密码；凭据通过管道传递，不写入代码或命令行 |
| `log(...values)` | 更新连接执行信息，console 常用方法也接入此处 |
| `sleep(ms)` | 等待，最长5分钟 |

```js
export default async ({ launch, log }) => {
  await launch("C:/Windows/System32/notepad.exe", []);
  log("Done");
};
```

最多并行4个脚本，每个最多5分钟。停止、删除连接或退出应用会结束脚本及Node子进程；已启动的本机程序与已完成的副作用不会撤回。删除连接保留脚本文件。脚本仍可使用标准Node模块，应用不提供浏览器专用接口。

旧网页/本机程序配置保留ID、分组与凭据并兼容迁移。已存在的脚本文件不覆盖；旧网页自动生成的Chrome调用不再可用，需要用户修改代码。尚未迁移的旧网页记录转换为明确停用的脚本，原配置保存在legacyEntry元数据，不直接删除用户记录。

## SSH 分组前置代码

在 SSH 的“管理”中，点击一级分组的“设置”，通过“连接前执行”选择现有动态代码入口。只保存代码连接 ID，脚本内容及凭据仍由原入口维护。未配置的分组行为不变。

再次打开仍然活动的 SSH 终端或文件传输时，直接复用已有连接。新建 SSH 连接、断线后重连或打开组内其他代码入口时，先执行前置代码，收到本次任务成功事件后才继续。已有任务正在执行则等待同一任务，上次成功不作为本次成功。失败、取消、缺失引用或配置变更都阻止继续连接；切走连接侧栏、切换目标或关闭窗口会取消等待，并按任务 ID 取消对应脚本，迟到结果不能切到新会话。等待期间显示前置代码和进度，可取消连接。密码沿用代码入口的保存、不使用密码或每次询问设置。直接点击前置代码自身只执行一次；展开、拖动和编辑分组不会执行脚本。

被分组引用的代码连接必须先解除或更改分组设置，再删除，删除检查在停止任务、断开会话和删除凭据之前执行。旧配置没有 `beforeConnectCodeId` 时仍可加载。失效引用保留，建立新连接时会明确报错。

## 编辑与排障

从连接设置确认实际脚本路径，修改前先备份。应用运行时可以编辑外部脚本，下次执行会加载新版。连接配置通过应用界面修改。

脚本可用 `log()` 记录阶段和错误。密码、令牌及其他连接凭据通过管道传递。日志只保留排查所需的阶段与结果。

为启动和就绪检查分别设置有限等待。程序启动、子进程退出、连接可用是三个不同的状态，前置脚本应在其所需服务确实可用后再返回。
