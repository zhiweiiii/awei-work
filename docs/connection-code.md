# 动态执行代码

连接页提供 SSH 终端和动态执行代码。动态代码使用独立 UTF-8 `.mjs` 文件，需要 Node.js 22+，按当前 Windows 用户权限执行。应用核心已移除浏览器连接，不再提供 Chrome RPC、扩展、网页步骤或 OCR；独立脚本可以自行实现所需能力，浦房示例见下文。

默认目录是 `%LOCALAPPDATA%\app.crynta.terax\connection-scripts\`，每个连接一个文件，也可填写项目中的 `.mjs` 完整路径。agent 可直接修改文件；每次执行创建新的 Node 进程加载当前代码，不监控文件并自动运行。界面保存比较内容哈希，文件被外部修改后需重新读取。

| 接口 | 用途 |
| --- | --- |
| `launch(exePath, args = [])` | 用完整 `.exe` 路径和独立参数数组启动本机程序，不拼 shell |
| `username` / `password` | 当前连接的用户名和本次取得的密码；凭据通过管道传递，不写入代码或命令行 |
| `log(...values)` | 更新连接执行信息，console 常用方法也接入此处 |
| `sleep(ms)` | 等待，最长5分钟 |

```js
export default async ({ launch, log }) => {
  await launch("C:/Windows/System32/notepad.exe", []);
  log("Done");
};
```

最多并行4个脚本，每个最多5分钟。停止、删除连接或退出应用会结束脚本及Node子进程；已启动的本机程序与已完成的副作用不会撤回。删除连接保留脚本文件。脚本仍可使用标准Node模块，应用不提供浏览器专用接口。

旧网页/本机程序配置保留ID、分组与凭据并兼容迁移。已存在的脚本文件不覆盖；旧网页自动生成的Chrome调用不再可用，需要用户修改代码。尚未迁移的旧网页记录转换为明确停用的脚本，原配置保存在legacyEntry元数据，不直接删除用户记录。

浦房测试可使用[独立自动登录脚本](../examples/connections/pufang/README.md)，兼容旧版和 1.1.0。该脚本自带限于本机的扩展通信及 Windows OCR，不依赖应用核心的旧 `chrome()` 接口；脚本目录保留在应用外部，更新安装包后仍可继续使用。更新扩展后需要在 Chrome 扩展页重新加载。

## SSH 分组前置代码

在 SSH 的“管理”中，点击一级分组的“设置”，通过“连接前执行”选择现有动态代码入口，例如把百佳华分组关联到百佳华vpn。只保存代码连接 ID，脚本内容及凭据仍由原入口维护。未配置的分组行为不变。

再次打开仍然活动的 SSH 终端或文件传输时，直接复用已有连接。新建 SSH 连接、断线后重连或打开组内其他代码入口时，先执行前置代码，收到本次任务成功事件后才继续。已有任务正在执行则等待同一任务，上次成功不作为本次成功。失败、取消、缺失引用或配置变更都阻止继续连接；切走连接侧栏、切换目标或关闭窗口会取消等待，并按任务 ID 取消对应脚本，迟到结果不能切到新会话。等待期间显示前置代码和进度，可取消连接。密码沿用代码入口的保存、不使用密码或每次询问设置。直接点击前置代码自身只执行一次；展开、拖动和编辑分组不会执行脚本。

被分组引用的代码连接必须先解除或更改分组设置，再删除，删除检查在停止任务、断开会话和删除凭据之前执行。旧配置没有 `beforeConnectCodeId` 时仍可加载。失效引用保留，建立新连接时会明确报错。

## Agent 接手顺序

1. 先读本文件和 [近期问题](issues.md)，确认任务是改连接脚本还是改应用核心，避免为了一个站点恢复整套已移除的浏览器功能。
2. 在 `%APPDATA%\app.crynta.terax\awei-work-ssh.json` 的 `connections.profiles` 中按连接名称找到记录，核对 ID、类型和实际脚本路径。不要假定所有连接都使用默认路径，也不要输出整个配置。
3. 检查正在运行的应用版本、用户指定的浏览器、当前页面及已安装组件。仓库版本、安装包版本和正在运行的版本可能不同。
4. 备份要改的脚本，读取整个调用链；入口 `.mjs` 之外可能还有 PowerShell、扩展或 OCR 文件。只改脚本不需要重打安装包，下次点击连接会加载新版。
5. 先重现一个明确失败点，再做最小修改。交接时写清改了哪个文件、实际验证到哪一步、剩下的具体阻塞，不把推测写成原因。

应用运行时可以改外部脚本，但不要直接覆盖它的连接配置，退出保存可能把磁盘修改覆盖回去。配置调整优先使用应用界面；确需批量导入时，先退出应用并备份配置。

## 编写与排障方法

### 先确认页面，再写操作

- 用户明确要求当前 Chrome 或 IE 时，沿用该浏览器，不静默换成独立浏览器、无头模式或其他账号会话。agent 操作页面前读取当前可用浏览器工具的技能说明；缺少支持时如实说明。
- 优先使用现场确认过的字段 ID、标签或可访问名称，不靠屏幕坐标和猜测的选择器。登录按钮应限定在对应表单内；多个候选时先查清，不能随便点第一个。
- 等待目标元素和实际内容就绪，不用固定睡眠代表页面加载完成。阶段分别记录为打开页面、定位表单、填写、提交、等待客户端，失败时指出卡在哪一步。
- “页面有表单”和“脚本拿到了可用表单对象”是两件事。截图显示表单、脚本却超时，应检查窗口引用、框架和元素定位，不要直接让用户重装组件。
- 提交前复核目标协议、主机和端口。页面跳转、验证码刷新或任务取消后，旧异步结果不能继续填写。
- 优先识别已登录状态，跳过不需要的登录步骤。登录结果不明确时停下，不自动重复提交账号密码，避免锁号或重复操作。

### Windows 子进程与凭据

- 应用通过管道提供当前连接的 `username`、`password`。Node 再调用 PowerShell 时同样使用 stdin JSON，不把密码拼到参数、环境变量、脚本、日志或临时文件中。
- 按完整可执行文件路径和参数数组启动，`windowsHide: true` 用于后台辅助进程；用户需要看见并操作的 IE 或 VPN 窗口正常显示。不要隐藏交互程序来规避用户确认。
- 旧 IE COM 脚本使用 Windows PowerShell 5.1 的 STA 模式；不要用 PowerShell 7 的运行结果直接断言旧 IE 自动化是否可用。含中文的 `.ps1` 给 5.1 使用时保存为 UTF-8 BOM，stdin/stdout 明确使用 UTF-8。
- 进度按行实时传给 `log()`，stderr 保留有界错误并脱敏。不要在重试循环中吞掉所有异常，最终只返回“未找到表单”；至少保留最后一个具体读取错误。
- 为启动、等待页面、识别和客户端启动分别设有限等待。超时只回收本次创建的辅助进程，不无差别结束用户的浏览器、VPN 或 agent。
- 外部程序可能继承输出管道。区分子进程退出、管道关闭和业务完成，不能把迟迟收不到 EOF 当成任务还在运行，也不能把进程退出码 0 当成 VPN 已连接。

### Chrome 扩展与本机桥接

浦房示例由 Node 脚本、可加载扩展和 Windows OCR 组成，应用仅提供凭据、启动和日志，不依赖旧 `chrome()` API。

- 修改扩展文件后，Chrome 中已加载的扩展不会因此自动更新，需要在 `chrome://extensions/` 重新加载。单纯重新打开网页不能证明新扩展代码已生效。
- 本机服务仅在任务期间监听回环地址。现有示例尝试 34271、34270，不能改成对局域网开放；校验 Host、扩展来源、配对密钥和任务身份。
- 保留用户已有配对密钥，不把 `chrome-entry-key`、生成的 `bridge-config.js` 或凭据提交到仓库。公开 manifest 中用于固定扩展 ID 的公钥不是用户配对密钥。
- 凭据只允许当前任务领取一次，任务完成、取消或超时后关闭服务；不因页面重载而重放登录步骤。排查端口占用先找具体任务，不直接结束所有 Node 进程。

### 验证码图片与 OCR

浦房页面实际原图为 300×100，显示约为 76×26。按显示尺寸设原图上限会错误拒绝图片；过度放大也会降低识别率。

- 先等待图片 `complete` 且 `naturalWidth/naturalHeight` 有效；用自然尺寸判断源图片，用适度缩放和留白准备 OCR 输入。当前示例目标约 320×128，再加边距，不是越大越好。
- 本机可能只安装中文 OCR 语言，不能假定英文语言包存在。使用系统已有语言后，仅提取预期的四位数字。
- 细干扰线会使原图 OCR 丢字。示例在内存中生成原图及两种阈值清理图，通过小范围腐蚀、膨胀处理干扰线；只接受唯一四位数字候选，不猜测、不投票补位。
- 当前三像素清理可能同时擦掉细字笔画；原有三次识别无候选时，才追加二像素清理和尺寸受限的二倍缩放，最多八次。已有候选冲突时停止，不通过更多变体投票覆盖冲突。日志只记录阶段、尝试数、候选数、尺寸和系统语言；结构化结果区分没有候选、冲突和 OCR 运行异常，不保留图片或验证码值。
- 识别期间记录图片来源及加载变化，图片刷新后丢弃旧结果。识别失败保留页面供用户继续，不自动刷新验证码并反复尝试登录。
- 不把验证码图片上传到第三方或写入日常日志。agent 现场处理验证码时，按当前浏览器工具要求取得当次确认；之前的登录授权不代表所有后续验证都自动获准。

### IE、证书与 VPN 客户端

- IE 跨区域跳转可能更换进程，最初创建的 COM 对象未必仍对应用户看到的窗口。定位实际目标登录页，并在等待期间更新窗口引用；不能只依赖原对象的 `Busy/ReadyState`。这是需要排查的兼容性因素，不是本次已证实的唯一根因。
- 百佳华页面已确认用户名 ID 为 `svpn_name`，密码 ID 为 `svpn_password`。优先按这两个字段定位，检查可见和可输入状态；`randcode` 存在但当时隐藏，不能仅因 DOM 中有这个字段就要求验证码。
- IE 的证书信任与证书域名匹配是两项检查。现场证书为自签名 `CN=SANGFOR`，未覆盖 `vpn.szbjh.com`。该证书已加入当前用户根证书库，用户另行手动关闭了地址不匹配警告；页面能打开不代表服务端证书问题已修好。
- 新脚本不自动改变系统证书/TLS 设置，不自动跳过安全提示。工具审批拒绝操作时，记录被拒的具体动作和返回原因，不通过换语法、换工具或包装脚本重试同一被拒操作；需要手动完成的步骤交给用户。
- 网页登录成功、客户端启动、VPN 隧道连接成功分别验证。截图中的“自动安装组件失败”是客户端环节的线索，不能靠修正表单定位解决，也不能把页面上始终存在的帮助文案直接当成登录失败结果。
- 本机已安装 `SangforCSClient` 和 `EasyConnect`，但安装存在不代表该站点组件可用。不要猜客户端参数，直接启动另一个已保存的公司配置，或改写其连接记录；先确认当前站点实际的启动流程。
- 检查客户端时同时考虑新进程和已有实例复用。仅出现新 PID 只能证明进程启动，不能证明已连接百佳华 VPN；最终应检查客户端显示的目标和连接状态。
